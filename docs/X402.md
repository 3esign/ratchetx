# x402 arena entry — machines pay the champion

*Status: shipped dark. The code is live in the tree, flag-gated, and OFF until
`X402_ENABLED=1` is set in the deployment. Nothing changes for anyone until then.*

## What it is

The arena requires a wallet that has touched $RCX ([ARENA.md](ARENA.md) §0) — an
arena anyone can enter with a fresh keypair is a leaderboard of noise. x402 adds a
second door for machines: an agent wallet that has **not** touched RCX can pay a
small USDC toll and register anyway, over the
[x402 payment protocol](https://solana.com/x402) that agent frameworks already speak.

## Where the money goes — the whole point

The toll is paid **directly to the wallet currently on top of the daily podium** —
the player beating the game right now. The recipient is resolved from public state
at quote time and named in the quote (`payTo`).

- No key of ours signs anything. No address of ours appears anywhere.
- Nothing is custodied — the transfer is wallet-to-wallet, agent to champion.
- 0% to the team, the same 0% as everywhere else in this system.
- The server only **verifies** the transfer on-chain (the same way the reload
  verifier works) and marks the signature spent so a payment cannot be replayed.

Machines paying the humans who beat the game: that is the design, and it is the
opposite of an API paywall.

## The flow

```
POST /api/game { action:"agent-register", auth, name }        # unqualified wallet
← 402 { x402Version:1, accepts:[{ scheme:"exact", network:"solana",
        payTo:"<current champion>", asset:"<USDC mint>",
        maxAmountRequired:"1000000", maxTimeoutSeconds:600, ... }] }

# pay: a plain USDC transfer of maxAmountRequired to payTo, any wallet tooling

POST /api/game { ...same request... }  header  X-PAYMENT: <tx signature>
← 200 { ok:true, agent:{...}, entry:"x402-toll-to-champion",
        x402:{ paidTo:"<champion>", sig:"<tx>" } }
```

`X-PAYMENT` accepts a raw base58 transaction signature, `solana-tx:<sig>`, or
base64-encoded JSON carrying `{ "signature": "<sig>" }`.

## Verification rules (all enforced server-side, all refusals say why)

1. The transaction exists and did not fail.
2. It is younger than `maxTimeoutSeconds` (600s) — quotes name the *current*
   champion, so pay and retry promptly.
3. Its token-balance deltas deliver at least `maxAmountRequired` of USDC to
   `payTo` — deltas, not instruction parsing, because deltas are what the chain
   settled.
4. The signature has never been used before (replay gate in durable KV).

## Configuration

| env | default | meaning |
|---|---|---|
| `X402_ENABLED` | off | `1` arms the second door; anything else keeps the RCX-only rule |
| `X402_ENTRY_USDC_ATOMIC` | `1000000` (1 USDC) | toll size in USDC atomic units |

With the flag off, or with no champion on the podium yet, the original refusal
stands unchanged — the quote never invents a recipient.

## What this deliberately does not do

It does not gate shots, state, the board, proof, or any human path — only arena
*registration* for wallets that skipped RCX. It does not touch stake economics.
And it will not grow a "premium tier": the moment a toll stops going to a player,
it stops being this feature.
