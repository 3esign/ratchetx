# Core G2 admission client — Astra, 2026-09-05

`createCoreG2AdmissionClient(options)` adds `grantDelegateIx`, `sealObservedIx`, `sealObservedDelegatedIx`, `sealForwardDelegatedIx`, `observedTiming` and `validateDelegateGrantAccount` to the frozen R2 base/lifecycle modules. Options carry injected web3, crypto, Core/Timepin identities and nonzero canonical Economy/Ruleset hashes. It creates instructions only; the caller owns reads, chain clock, prerequisite accounts, simulation, wallet and transport.

All seals take decoded, hash-checked Economy/Ruleset/EvidenceSpec, a raw canonical Ledger, raw entry/exit Needs, nonce, stake and commitment. Observed mode additionally requires the raw FINAL entry Candidate; delegated modes require the raw canonical DelegateGrant and delegate identity. Raw accounts use `{address, info: {owner, executable, data: Uint8Array}}`. A new grant requires an explicit current-account read; `info:null` means observed absence, while unavailable/undefined reads are rejected. Merely funded empty system accounts are accepted as logically uninitialized.

Observed timing uses Candidate publish time for freshness and aligns `chainNow + horizon` to the grid for exit. The score day comes from exit plus source lag, capture grace and reveal window. Crossing a grid boundary requires refreshing the exit Need. The builder derives these fields instead of trusting caller-provided exit/day values. Forward delegation reuses R2 admission timing and requires both OPEN Needs.

Grant changes preserve cumulative gross stake, shot count and last-seal time. A revoked grant cannot be revived. Admission checks expiry, minimum interval, per-shot and cumulative stake, shot count, canonical PDA/owner/discriminator/layout, next nonce, credits and open limit. The existing R2 terminal module handles later reveal/settlement; revoking a grant does not retroactively change the delegate frozen into an existing Shot.

Ten actual native tests pass with installed web3 and captured Rust declarations: exact Borsh bytes and Rust account-meta order for all three seals plus grant, raw account tampering, grant updates, interval/expiry ceilings, observed freshness/clock boundaries, forward Needs and integer limits. No test skipped. Earlier failures are retained: the test serializer lacked Ledger u128 support, then the forward fixture incorrectly attached a terminal message hash to an OPEN Need; the raw validator correctly rejected it.

Honest verdict: this is source-derived JS validation against the captured cGf generation, not ANV SBF, rent/CPI execution, transport or a mainnet acceptance certificate. Runtime program IDs are injected. Sol must deliberately re-pin captured source guards to the final ANV commit and rerun; old receipts remain immutable. Full reserve/XP overflow accounting stays enforced by the actual program/simulation, not duplicated here. Raw RPC consistency and registered-account provenance remain caller responsibilities; an arbitrary decoded object with matching content hash alone is not a chain proof. No ledger/history/Need auto-creation or real signing is included.
