## Mathematical finding, separate from live sampling

For integer timestamps and `prev = pub - 1`, `prev < T <= pub` holds exactly when `pub = T`. If the sponsored account only exposes `pub = 5k + 2`, every `T = 60m` fails. Polling or cranking faster cannot recover an aggregation that was never posted to that source. This implication is confirmed by independent executable counterexamples, 4/4 passing in `test-bracket-counterexample.mjs`. The synthetic day in that test is **not a 24-hour mainnet sample**.

The external 25–30-minute report is credible but its exact feed counts and continuous coverage are not independently accepted yet. Svemir owns the independent read-only seven-feed sampling. Report unique observed `(pub,prev)` pairs, full account/authentication facts, RPC/context slots, observed minute targets, poll gaps/rate limits and phase histograms. Polling may miss short-lived account values; zero observed hits is not proof of perpetual zero availability. A phase offset alone is not a durable oracle guarantee.

## What the proposed earliest-captured rule proves

It deterministically selects the smallest timestamp **among submitted and authenticated observations**. It cannot prove that no earlier eligible print existed. Example at `T=60`: actual prices `(62,90)` and `(67,110)`, entry100. Prompt capture settles DOWN; omitting the first print and submitting the second settles UP. Both satisfy a30-second post-target window. Once the canonical account has overwritten the62 print, a later honest caller cannot submit it through the current source path. The same price-selection freedom can extend across the whole admitted window, not merely one5-second tick.

Permissionless access means anyone can capture; it does not guarantee an honest transaction lands while the first eligible print is present. An independent capturer removes selection only when its timely capture actually succeeds and remains canonical. A refund does not bound damage from an accepted later, real but selectively chosen price. Commitment secrecy hides other players' directions but does not hide a player's own position from that player.

Current `docs/SETTLEMENT.md` SHA256 `7f860d307b1d6a0126fb8a54f156a9b95c0428b93a30d0fc70fe9ac71723af49` describes an earliest-checkpoint primary path and a historical-first precision path, while its opening says price is not a choice and early/late settlement yields the same value. Those are different guarantees. `docs/ONCHAIN_COST.md` SHA256 `1c62f1da946b75b65ce7c99fe37ebc9d136d9cf25e76740d50f0cdc89dd43674` also treats minute checkpoint coverage as if aggregation predecessor covered a sponsored push interval. Paying more capturers cannot repair missing source data.

Primary documentation: [Pyth Solana integration](https://docs.pyth.network/price-feeds/core/use-real-time-data/pull-integration/solana) separates latest sponsored accounts from posted price-update accounts. [Sponsored push feeds](https://docs.pyth.network/price-feeds/core/push-feeds) are heartbeat/deviation driven with possible delays. [Hermes timestamp API](https://docs.pyth.network/api-reference/pyth-core/hermes/timestamp_price_updates) returns the first update at/after the requested time; on-chain authentication still determines acceptable proof. The [existing project forum thread](https://dev-forum.pyth.network/t/were-building-a-prediction-game-on-solana-where-every-shot-settles-on-pyth-and-we-ended-up-doing-the-account-validation-by-hand-rather-than-through-the-sdk-sharing-what-we-found-plus-four-questions-we-couldnt-answer-from-the-docs-why-by-hand-our-fi/825), posts6–7, retracts an initially suggested public Benchmarks fallback and states timestamp authentication is required. Do not revive the superseded free-history claim.

## Recommendation to Sol: explicit choice, no silent weakening

1. Keep strict first-crossing semantics intact under its existing adapter identity. Do not change what an existing adapter/hash means. Do not describe sampled sponsored availability as guaranteed.
2. If the agreed game is the earlier documented **first captured sponsored observation**, implement it as a separately identified adapter/ruleset with a precise, public assumption: timely independent capture is needed to prevent selective omission. This is a product/security tradeoff, not equivalent to historical-first settlement. Do not label it a proof of the globally earliest print. Its observation and admission windows must be fixed before the wager.
3. If unconditional no-price-selection is required, minimum-of-captures alone is rejected. It needs an authenticated completeness/first-crossing proof or a different explicitly specified game/oracle design. Current latest-only account bytes contain no proof of omitted history. No new API payment, provider subscription, or historical adapter is authorized by this review.

For an observation adapter, the bounded implementation contract must settle these points before edits: separate adapter ID in immutable spec/hash; state transition for earlier/later/duplicate candidates; AMBIGUOUS retained for distinct messages at the same winning timestamp, with no lexicographic price-selection tie-break; no late override after finalization; capture/source deadline boundaries; generation/feed/Full-verification checks unchanged; bounded account/rent growth and cleanup for superseded candidates; terminal hashes and WorkPage completion consistency; Core foreign validator, all client validators, model vectors and exact-SBF tests updated together. A historical adapter cannot simply reuse canonical-sponsored-PDA checks.

Minimum acceptance tests: reported phase2 stream; missed first observation reversing outcome; early+late+duplicate order; equal-time conflicting messages; missing capturer; delayed/failed RPC; capture race and deadline edges; immutable final result; rejection of wrong feed/owner/PDA/generation; rent/account bound; downstream Core terminal reconstruction. Twenty-four-hour sampling can run in parallel to estimate availability, but cannot prove censorship resistance or settle the design choice by itself.
