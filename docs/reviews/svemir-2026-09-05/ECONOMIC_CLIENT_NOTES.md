# Economic client handoff

Two new files only: `onchain/ratchet-core-g2/client/economic-v2.mjs` and `test/test_core_g2_economic_client.mjs`. Sol imports them after R2's reviewed base `client-v2.mjs` (SHA-256 `75b43c937a3e613980f5704147e18c803f56d684e5e422efaaae102eea1f4b6b`). No existing source, Cargo file, candidate or frozen R2 was changed.

`createCoreG2EconomicClient({web3, coreProgramId, timepinProgramId, cryptoImpl})` is browser-neutral and has no transport, wallet, signing or execution. Program IDs are injected. Its caller must authenticate the deployed ELF/authority/cluster, use fresh account reads and Clock, simulate, and control signing. This package does not establish that the browser is already wired to it.

Available behavior:

- Five exact Core instruction constructors: `registerEconomyIx`, `registerRulesetIx`, `openReloadPageIx`, `finalizeDayIx`, `reloadRcxIx`. Registration checks the expected serialized argument hash; ruleset proof encoding is bounded to 32 siblings. Full policy/economic validation still belongs to the on-chain program. Reload requires raw authenticated DayFinal for exactly yesterday plus an explicit expected hash, uses Token-2022 and the canonical RCX mint, and always includes all three canonical podium destinations.
- `prepareDayFinal({economyHash, day, chainNowTs, shardAccounts})` authenticates exactly 16 ordered `{address, info}` reads and computes the immutable rank/day hashes. Explicit null or System-owned non-executable zero-data accounts are logical absence only at the correct PDA; lamport prefunding does not veto empty-day close. It returns `ready`, `day-open`, or `needs-terminalization`. Only `ready` contains a final hash; unresolved output identifies each shard's remaining count. It does not discover/crank those players automatically.
- `validateDayFinalAccount` rehashes the 299-byte account and validates canonical identity, sorted unique podium, counters and finalization fields. `validateReloadHistoryAccount` checks the exact 87 + 51*n byte account, up to 32 records. `reconstructReload` authenticates the permanent record and matching DayFinal, verifies allowed burn/route/retain actions for each seat, and computes exact gross/consumed/burned/routed/retained/credits using BigInt.
- `reloadAllocation(gross, actions)` is pure integer arithmetic. Actions are explicit historical or externally established facts; this function does not infer that a destination exists or can receive tokens. It is not a verified live account quote.

First-funded-play sequencing is still explicit: finalize the ended previous day and confirm/read its DayFinal; open a player's ledger if absent; open its reload page only if absent; reload and confirm before sealing. `open_reload_page` and `finalize_day` use Anchor `init`, so blindly including them again is not idempotent. Read the ledger's current `nextReloadNonce`; record index is nonce % 32 and page is nonce / 32. A page with a different record count cannot be appended to by guessing a nonce. Refresh Clock/day at midnight and rebuild if yesterday changed. The player token source defaults to the player's canonical ATA; a caller-supplied source still has to pass the program's token ownership/mint/balance checks. Mint extensions, CPI behavior and rent transfers need the exact-SBF/live proof owned by Sol.

Liveness consequence: yesterday's unfinished accepted shots block that day's immutable podium, which blocks new reloads dependent on it. This follows existing game rules and was not changed. The module reports the deficit and refuses to construct a daily close; it does not invent a founder bypass or claim time alone settled anything. Self-seat RCX is retained, so credits depend on consumed RCX, not always on the user's gross input. A VOID credit refund does not reverse the earlier token burn.

Native validation on 2026-09-05: Node v24.15.0, **15 tests pass, zero failures/skips**, receipt `TEST_RECEIPT-20260905012850680.json`, result `test-results-20260905012850680.txt` SHA-256 `7c9cd3f54572986e567d3a6d5a36b84febf596bfb494478163956a9f2049f4a7`. The suite derives account serialization and account metas from actual Rust declarations, compares independently serialized hash preimages, exercises all 27 action combinations across 11 integer boundaries, validates malformed/forged accounts, unfinished-day refusal and history page boundaries. This is one JS suite, not 297 independent test cases or native SBF execution.

The first actual run was 9 pass / 6 fail: the new wrapper incorrectly used R2's asynchronous player-based `rankShardPda` as an index-based synchronous helper. Fixed by adding explicit `rankShardPdaForIndex` with Rust's exact seeds. Positive source-derived day fixtures now pass; the failed receipt remains preserved.

**Identity boundary:** this tested source snapshot still has the former cGf declaration. Astra's later public identity review recommends ANV as the held G2 identity. Before final candidate acceptance, Sol must deliberately re-pin the test's Core ID and source guard against the new reviewed source commit, then rerun this suite and exact-SBF parity. The library accepts the selected Core ID, but a previous receipt must not be relabeled as proof of a different generation. R2's other 23 tests were not rerun by this package. No deployment or actual token movement was performed.
