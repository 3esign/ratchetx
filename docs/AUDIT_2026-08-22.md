# RATCHET h52 - audit and release-candidate report

Date: 2026-08-22
Status: LOCAL RELEASE CANDIDATE - NOT DEPLOYED BY THIS AUDIT

## Verdict

No known P0 defect remains in the locally tested web game path. The core mechanics,
reward accounting, recovery path, public evidence, and responsive layout pass the
automated suite. This is not a claim of a third-party smart-contract audit.

Production must remain honest about two architectural limits: the displayed SOL
floor is a model and is not redeemable, and the deployed mainnet program is the
legacy settlement program, not a vault or the proposed v2 referee.

## Scope reviewed

- `ratchet/`: APIs, settlement, reward split, Redis state, snapshot/restore, proof
  surfaces, public copy, responsive UI, and all local automated tests.
- `skills/solana/`: complete inventory; applicable doctrine, RPC, oracle, program,
  token, gaming, measurement, and economy guidance; all executable zero-dependency
  templates; Anchor and shell template surfaces.

## Core changes in h52

- Daily podium is live and dynamic by settled XP, resets at 00:00 UTC, and fills
  empty new-day seats from yesterday in rank order without duplicate wallets.
- The 30% champion cut has exactly three seats: 50% / 30% / 20%. Replaced
  snapshots remain signable for ten minutes; transaction time and allocation are
  verified against the immutable snapshot.
- The old continuing-hold / safe-to-sell condition was removed.
- Weekly credit pot and the frozen 70% burn / 15% daily / 15% weekly rule were not
  changed.
- Public all-time XP ranking was added as a record-only board with no prize.
- Reward receipts now distinguish incoming RCX, self-retained RCX, external podium
  payments, credits, burn, and transaction links.
- Self-routed TransferChecked payments are accounted as retained rewards instead of
  incorrectly appearing as zero reward.
- Snapshot/restore now includes sorted sets, all-time ranking, podium fallback and
  podium history, and refuses missing/tampered hashes or unsigned write restores.
- Public copy now labels Pyth fallback as display-only, the floor as modeled and
  non-redeemable, the legacy program/mirror status, actual stake limits, and server
  trust boundaries.
- Header is two structural rows: wallet is last at top-right; navigation and token
  facts share row two. Layout is responsive from 360 to 1920 px.

## Known risks and release gates

### P1 - must not be misrepresented

1. No redeemable SOL vault exists. Do not market the model floor as backing, a
   withdrawal promise, or a player claim until a separate funded and audited vault
   program proves assets and liabilities.
2. Mainnet deployment alone does not make the current program a complete referee.
   The legacy program has a settle/void overlap after one hour and lacks the planned
   confidence/final-deadline controls. Mirror writes remain disabled.
3. No independent external smart-contract or application security audit has been
   completed.

### P2 - operational / evidence debt

1. Historical production log entry 345 is an irrecoverable evidence gap and must
   remain disclosed.
2. Vercel, RPC, Pyth, and Redis remain external operational dependencies. The
   heartbeat needs a durable supervisor/host; a laptop background task is not a
   production availability guarantee.
3. Production currently remains h51 until an authorized h52 deployment followed by
   domain, TLS, API, wallet, reload, settlement, proof, and mobile smoke tests.
4. Exact official X and Telegram destinations are still intentionally unset.

## DEX readiness before paid listing

Do not pay for a listing until the production smoke gate is green and a separate
token checklist verifies mint address, decimals, metadata, update/freeze/mint
authorities, treasury and deployer wallets, liquidity ownership/lock claims, public
links, rate limits, monitoring, and truthful risk language. The vault and v2 referee
are roadmap candidates, not features to imply as live.
